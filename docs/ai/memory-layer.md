# 可选：跨项目经验记忆层

> 这是**进阶、可选**能力。`global-core.md` 里提到「经验层可选」，本文说明怎么接。默认不开，也不随仓库附带任何后端。

## 概念

知识分两层：

- **真相源**：仓库里 checked-in 的 markdown（根 `AGENTS.md`、`docs/ai/*.md`、`.agents/local/`）。项目事实只写这里。
- **经验层**（可选）：一个跨项目共享的记忆服务，用来沉淀**换项目仍然成立**的方法、坑与结论——比如"某工具在这个平台上这样调用会失败""某类迁移的可靠顺序"。

经验层**不是**事实真相源：项目里的具体事实永远写进 checked-in md，不写记忆服务。

## 为什么仓库不内置后端

- 记忆服务通常绑定私有机房、账号和凭据；写进公开仓库会泄密，对别人也没用。
- 每家可以接自己已有的东西（自建服务、向量库、甚至一个 git 仓库的 md 文件）。

所以仓库只约定**接口**，由使用者自己实现。

## 接口约定

想让模型能用经验层，你需要在会话里给它一个（或几个）检索/写入工具，行为对齐下面几点：

- **检索**：输入关键词（项目名 / 技术栈 / 报错片段），返回相关条目；按相关度排序；无结果时明确返回空，不要编。
- **写入**：输入一条自包含的结论（问题、现象、结论/方法），可带来源场景标签。
- **边界**：只存换项目仍成立的方法与结论；不存一次性流水、完整日志、密钥/凭据/PII。
- **自治**：模型自行决定何时查、何时写，不逐项问用户；写入失败不阻塞主任务。

如果你的工具支持 MCP 或类似机制，把这些能力注册为一个服务即可；`global-core.md` 的经验层条款会自动约束模型怎么用它。

## 一个最简实现思路

不需要一开始就上向量库：

- 用一个目录存 `*.md`，每条结论一个文件，文件名带关键词。
- 检索 = `grep` / 关键词匹配；写入 = 新建文件。
- 用你自己的脚本把它暴露成 MCP 工具或 shell 命令。

够用之后，再换成向量 + BM25 混合检索。

## 隐私红线（务必遵守）

- 不写真实凭据、token、私钥、个人数据。
- 不写内部主机名、IP、可直接利用的漏洞细节。
- 记忆内容可能被多项目共享：写之前先想"这条换到别人项目里还成立吗、会不会带出敏感信息"。
